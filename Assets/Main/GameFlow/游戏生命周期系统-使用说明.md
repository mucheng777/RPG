# 游戏生命周期管理系统 · 使用说明

> 目标：为项目补齐「开始页面 → 游戏运行 → 暂停 → 玩家死亡 → 玩家复活 → 重新开始」的完整闭环。
> 全部 UI 使用 Unity 原生组件（Canvas / Image / Button / Text），美术素材可随时替换，脚本零改动。
> 接入原则：不改动 PlayerController / PlayerLocomotion / PlayerCombat / Animator 等既有核心脚本；
> 仅对 `PlayerHealth`、`HealthBarUI` 做了**最小加法改动**（新增/重写钩子，不改变既有行为）。

---

## 一、模块总览

### 目录结构

```
Assets/Main/GameFlow/
├── GameFlowScripts/
│   ├── GameState.cs              # 流程状态枚举（单一真相源）
│   ├── IRevivable.cs             # 可复活契约（依赖倒置）
│   ├── GameFlowProfile.cs        # 流程配置（ScriptableObject，可调参）
│   ├── GameManager.cs            # 流程管理器（状态机 + 环境副作用 + 意图接口）
│   ├── PlayerLifecycleBridge.cs  # 玩家生命周期桥（死亡监听 + 复活复位）
│   └── PauseInputHandler.cs      # 暂停按键输入
├── UI/
│   ├── UIManager.cs              # UI 层总控（注册制 + 状态互斥仲裁，面板显隐唯一仲裁者）
│   ├── GamePanel.cs              # 面板基类（声明 ShownState、自动 CanvasGroup、图片占位适配接口）
│   ├── MainMenuPanel.cs          # 开始页面
│   ├── PausePanel.cs             # 暂停菜单
│   └── DeathPanel.cs             # 死亡提示
└── 游戏生命周期系统-使用说明.md   # 本文档
```

### 分层与职责（低耦合的关键）

| 层 | 组件 | 职责 | 依赖 |
|---|---|---|---|
| 逻辑层 | `GameManager` | 持有并切换 `GameState`，把状态翻译成 `timeScale`/音频/光标；提供意图方法 | 只依赖 `GameState`、`PlayerLifecycleBridge` 抽象调用 |
| 逻辑层 | `PlayerLifecycleBridge` | 监听玩家 `OnDied` 通知管理器；复活时做数据 + 空间复位 | 只依赖接口 `IHealthSystem` / `IRevivable` |
| 数据层 | `GameState` / `GameFlowProfile` / `IRevivable` | 状态定义、可调参数、契约 | 无 |
| 表现层 | `UIManager` | UI 层总控：统一仲裁所有面板显隐（注册制 + 状态互斥） | 依赖 `GameManager`（读状态）、`GamePanel`（注册表） |
| 表现层 | `MainMenuPanel` / `PausePanel` / `DeathPanel`（继承 `GamePanel`） | 声明自己显示于哪个状态；按钮点击只调管理器意图 | 依赖 `UIManager`（自动注册）与原生 UI 组件 |

**数据流向**：鼠标点击 → 面板调 `GameManager.StartGame()` → 管理器切状态 → 广播 `OnStateChanged` → **UIManager 统一刷新**：仅与当前状态匹配的面板显示，其余全部隐藏。
状态只有一个来源（`GameManager`），显隐只有一个仲裁者（`UIManager`），面板既不持有状态副本、也不自行决定显隐。

### UI 层级关系与总控机制（UIManager）

**推荐层级结构**（同一 Canvas 内，Hierarchy 兄弟顺序越靠后绘制越在上层）：

```
GameFlowCanvas（Canvas · Screen Space Overlay · 挂 UIManager 组件）
├── MainMenuPanel   [Main Menu Panel]  ShownState=MainMenu
├── PausePanel      [Pause Panel]      ShownState=Paused
├── DeathPanel      [Death Panel]      ShownState=PlayerDead
└── (可选扩展) HUDPanel                 ShownState=Playing
```

**总控规则**：

1. **注册制**：面板在 `OnEnable` 时自动向 UIManager 注册（无需拖引用），`OnDisable` 自动注销。
2. **状态互斥**：每次状态切换，UIManager 统一 RefreshAll —— 只有 `ShownState` 与当前状态匹配的面板显示，其余全部淡出。**结构上保证不堆叠、无残留**（点击「开始游戏」后主菜单必然关闭）。
3. **注册即对齐**：中途激活/动态创建的面板，注册瞬间按当前状态同步到正确显隐。
4. **配置诊断**：两个面板声明同一 `ShownState` 时，Console 立即告警。
5. **优先级（sortingPriority）**：作为注册表排序与未来"同屏叠加面板"（HUD+弹窗）的预留；当前互斥显示，同屏最多一个流程面板。

**各阶段 UI 显示规则**：

| 游戏阶段 | 显示 | 隐藏 |
|---|---|---|
| MainMenu（游戏启动前） | MainMenuPanel | PausePanel / DeathPanel |
| Playing（游戏进行中） | 无全屏面板（仅世界空间血条） | 所有流程面板 |
| Paused（暂停） | PausePanel | MainMenuPanel / DeathPanel |
| PlayerDead（游戏结束） | DeathPanel | MainMenuPanel / PausePanel |

**图片占位 → 美术素材接入**（无需图片资源即可运行）：

- 静态接入：把 Sprite 直接拖到面板脚本的 **Background Image** 字段；
- 动态接入：调用 `SetBackgroundSprite(Sprite)` / `SetBackgroundColor(Color)`；
- 脚本只依赖 `Image` / `Button` / `CanvasGroup` 原生组件，换素材零改码。

### 状态机

```
         开始游戏
MainMenu ─────────▶ Playing ◀──────────┐
   ▲                  │  ▲             │ 继续 / 复活
   │                  │  └──────────┐  │
   │        死亡      │   暂停      │  │
   │         ▼         ▼             │  │
   │     PlayerDead  Paused ─────────┘  │
   │           │                        │
   └───────────┴────────────────────────┘
   重新开始 / 返回主菜单 → 重载当前场景 → 回到 startState(MainMenu)
```

| 状态 | timeScale | 音频 | 光标 | 说明 |
|---|---|---|---|---|
| MainMenu | 0 | 暂停 | 显示 | 世界冻结，只看开始页 |
| Playing | 1 | 播放 | 锁定 | 正常游玩 |
| Paused | 0 | 暂停 | 显示 | 显示暂停菜单 |
| PlayerDead | 0 | 暂停 | 显示 | 显示死亡面板，等复活 |

> 死亡/暂停时 `timeScale = 0`：敌人 AI、玩家移动、动画、物理全部随之冻结，
> 因此**无需改动任何既有角色脚本**即可让玩家「死亡后无法操作」。

## 二、分步挂载与配置

### 步骤 0 · 等待编译

首次导入后等待 Unity 编译完成（Console 无报错）。若报错，通常是脚本未写完，直接重新导入/编译即可。

### 步骤 1 · 创建 GameManager 物体

1. 在 Hierarchy 空白处右键 → `Create Empty`，命名 **GameManager**，位置归零。
2. `Add Component` → 添加 **Game Manager**（`GameManager.cs`）。
3. 再 `Add Component` → 添加 **Pause Input**（`PauseInputHandler.cs`）。

> `profile` 字段可留空：留空时使用内置默认值（初始状态 MainMenu、暂停键 ESC），**开箱即跑**。
> 想调参再执行「步骤 6」。

### 步骤 2 · 给玩家挂生命周期桥

1. 选中场景中的 **Player** 物体。
2. `Add Component` → 添加 **Player Lifecycle Bridge**（`PlayerLifecycleBridge.cs`）。
3. （可选）若想指定固定复活点：在场景中 `Create Empty` 命名 `PlayerSpawnPoint`，拖到桥组件的 **Spawn Point** 字段；
   不填则默认使用玩家进入场景时的初始位置。

### 步骤 3 · 处理光标冲突（重要）

项目中既有的 `CursorLockManager` 会用 ESC 释放光标，并在**点击鼠标左键时重新锁定光标**，
这会与暂停/死亡面板的按钮点击冲突（点一次按钮光标就被抢锁）。

→ 在场景中找到挂有 `CursorLockManager` 的物体，**取消勾选该组件（禁用）**。
光标此后由 `GameManager` 统一接管（游戏内锁定、菜单中显示）。

> 说明：`ThirdPersonCamera` 也会在启用时锁一次光标，但 `GameManager` 在每帧 `LateUpdate` 末统一收口，可覆盖它。

### 步骤 4 · 搭建 UI（原生组件）

1. Hierarchy 右键 → `UI` → `Canvas`，命名 **GameFlowCanvas**：
   - `Canvas` → Render Mode = **Screen Space - Overlay**
   - `Canvas Scaler` → UI Scale Mode = **Scale With Screen Size**，Reference Resolution = **1920 × 1080**
   - `Graphic Raycaster` 由 Unity 自动添加（无需手动）。
   - 场景中已存在 `EventSystem`，**无需再建**（若无则右键 UI → Event System）。
   - 在 GameFlowCanvas 上 `Add Component` → **UI Manager**（**必需**：面板显隐的唯一仲裁者；漏挂时面板拒绝显示并在 Console 报错提示）。
2. 在 GameFlowCanvas 下右键 → `UI` → `Panel`，建立三个子面板并命名：
   **MainMenuPanel**、**PausePanel**、**DeathPanel**。
   - 每个面板的 RectTransform 拉满全屏：Anchor 预设选 **stretch-stretch**，Left/Top/Right/Bottom 全 0。
   - 建议给每个面板 `Add Component` → **Canvas Group**（v2 中 GamePanel 检测到缺失会运行时自动补挂，但建议手动加上使结构显式）。
   - 分别添加脚本组件：
     - MainMenuPanel → **Main Menu Panel**
     - PausePanel → **Pause Panel**
     - DeathPanel → **Death Panel**
   - ⚠ 面板脚本所在的物体本身**不要再手动 SetActive(false)**，显隐由脚本的 CanvasGroup 控制。
3. 在各面板内添加内容（全部用原生组件，后续可自由替换素材）：
   - **MainMenuPanel**：背景 `Image`（颜色黑、Alpha≈0.75）、标题 `Text`（如「RPG DEMO」）、
     按钮 `Button`：**StartButton（开始游戏）**、可选的 **QuitButton（退出）**。
   - **PausePanel**：背景 `Image`、标题 `Text`（「已暂停」）、
     按钮 `Button`：**ResumeButton（继续）**、**RestartButton（重新开始）**、**MainMenuButton（返回主菜单）**。
   - **DeathPanel**：背景 `Image`（可偏红/暗）、标题 `Text`（「你死了」）、
     按钮 `Button`：**RespawnButton（复活）**、**RestartButton（重新开始）**、**MainMenuButton（返回主菜单）**。

### 步骤 5 · 把按钮引用拖进面板脚本

选中每个面板，把上一步创建的按钮 `Button` 组件拖到脚本对应字段（**不要**在 Button 自身的 OnClick 里再手动绑一遍，避免重复触发）：

| 面板脚本 | 字段 | 对应按钮 |
|---|---|---|
| Main Menu Panel | `startButton` / `quitButton` | 开始游戏 / 退出 |
| Pause Panel | `resumeButton` / `restartButton` / `mainMenuButton` | 继续 / 重新开始 / 返回主菜单 |
| Death Panel | `respawnButton` / `restartButton` / `mainMenuButton` | 复活 / 重新开始 / 返回主菜单 |

> 留空的字段对应按钮不生效，方便按需裁剪功能。

### 步骤 6 · （可选）创建可调参数资产

`Assets` 右键 → `Create` → `RPG` → **Game Flow Profile**，命名 `GameFlowProfile`，
拖到 GameManager 的 **profile** 字段。可调参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `startState` | MainMenu | 初始状态；改为 Playing 可跳过开始页直接进游戏 |
| `pauseKey` | Escape | 暂停/继续按键 |
| `pauseAudioListener` | true | 暂停时是否暂停全局音频 |
| `lockCursorWhilePlaying` | true | Playing 时是否锁定并隐藏光标 |
| `autoRespawnDelay` | 0 | >0 时死亡后自动复活（秒）；0=仅手动点按钮复活 |
| `restartReloadsScene` | true | 重开/返回主菜单是否重载场景以彻底重置世界 |

另外两处可调参数（在对应组件上）：
- `Player Lifecycle Bridge → spawnPoint`：复活点（留空=初始位置）。
- `PlayerHealth → reviveInvincibility`（默认 1.5s）：复活后的无敌时间，防止刚复活被贴脸秒杀。

## 三、功能测试流程

> 前置：`Project Settings → Player → Active Input Handling = Both`（本项目已是 Both）。

### 测试 1 · 开始页面
进入 Play → **世界静止**，显示开始页面，鼠标光标可见可用；暂停/死亡面板不得同时出现。
→ 点「开始游戏」：开始页淡出**无残留**，`timeScale` 恢复 1，光标锁定，玩家可移动/攻击。

### 测试 2 · 暂停 / 恢复
游戏中按 **ESC** → 显示暂停菜单，世界冻结（敌人/角色都停住）。
→ 点「继续」：恢复游玩。
→ 点「重新开始」：场景重载，回到开始页面（世界彻底重置）。
→ 点「返回主菜单」：场景重载，回到开始页面。

### 测试 3 · 玩家死亡
- 方式 A：面向敌人，被敌人攻击直到血量归零（敌人每 2 秒造成 10 点物理伤害）。
- 方式 B（快速）：反复按 **T** 键（`HealthTestInput`，每次 20 点真实伤害，5 次清空 100 血）。

预期：血量归零瞬间 → 血条隐藏、世界冻结、**死亡面板淡入**；
玩家 Game Object **不被销毁**（这是本系统的关键改动），血量保持为 0。

### 测试 4 · 复活
在死亡面板点「复活」：
- 血量恢复满值、血条**重新显示**并动画回满；
- 玩家被传送回复活点（出生位置或指定 Spawn Point）；
- 获得约 1.5 秒无敌（期间靠近敌人也不会立刻掉血）；
- 游戏回到 Playing，可继续操作。

在死亡面板点「重新开始」/「返回主菜单」：场景重载，回到开始页面 → 验证完整闭环。

### 测试 5 · 死亡锁校验
死亡后在复活前按 T：Console 打印「已死亡，T 键伤害被死亡锁忽略」，**血量不再下降**
（验证 `_isAlive` 死亡锁生效）。

## 四、最小改动说明（对既有脚本的改动清单）

为满足「复活需要重置血量 + 解除死亡锁」以及「血条隐藏后需恢复」两个硬需求，做了两处**加法改动**：

1. `Assets/Main/Player/PlayerScripts/PlayerStatus/PlayerHealth.cs`
   - `class PlayerHealth : HealthComponent, IRevivable`
   - 新增 `Revive()`：满血 + 解除死亡锁 + 广播血条 + 复活无敌（**只新增方法**）。
   - 重写 `HandleDeath()` 为空：玩家死亡**不再被延迟销毁**，改由 `GameManager` 接管（**只改一个重写钩子**）。
   - 其余逻辑（无敌帧、TakeDamage）**完全未动**。

2. `Assets/Main/Health/UI/HealthBarUI.cs`
   - 新增私有 `_hidden` 标记 + `ShowBar()`；
   - `OnHealthChanged` 开头新增：若处于隐藏态则自动 `ShowBar()`（复活时血量事件到来即恢复显示）。
   - 既有掉血动画/残影逻辑**完全未动**。

> 未改动：`HealthComponent`、`EnemyHealth`、`EnemyBrain`、`PlayerController`、`PlayerLocomotion`、
> `PlayerCombat`、`AttackHitDetection`、`ThirdPersonCamera` 等。

## 五、扩展指南

- **新增流程状态**（如「结算」「过场」）：在 `GameState` 追加枚举 → 在 `GameManager.ApplyState` 补一条副作用规则。
- **新增流程面板**：新建脚本继承 `GamePanel`、重写 `ShownState` 即可，`GameManager` 无需改动（开闭原则）。
- **改为多场景结构**：把 `GameManager.RestartGame / ReturnToMainMenu` 内的 `SceneManager.LoadScene(buildIndex)`
  换成目标场景名，其余流程逻辑不变。
- **替换美术素材**：所有面板脚本只依赖 `RectTransform / CanvasGroup / Button`，
  背景图、字体、动效可随意替换；如需「开始页动态背景」，把 Player 的摄像机/UI 分层即可，脚本零改动。
- **与对象池配合**：`EnemyHealth` 已实现 `IPoolable`（预留）；本系统只处理**玩家**生命周期，
  敌人回收由后续池系统独立承担，两者互不干扰。

## 六、常见问题（排查清单）

| 现象 | 排查点 |
|---|---|
| 进了游戏光标一直锁着，无法点开始按钮 | GameManager 是否在场景中；`CursorLockManager` 是否已禁用；GameManager 是否被误删 |
| 按 ESC 鼠标被释放/显示，禁用 CursorLockManager 后依然如此 | 这是**暂停功能**在生效：`PauseInputHandler` 监听 ESC → 进入 Paused → 光标解锁（供点击暂停菜单）。与 CursorLockManager 无关；换按键改 `GameFlowProfile.pauseKey` |
| 点按钮无反应 | 面板脚本对应 `Button` 字段是否拖入；`Canvas` 上是否有 `Graphic Raycaster`；场景是否有 `EventSystem` |
| 面板从头到尾不显示 | UI 根物体是否挂了 **UI Manager**（必需）；`ShownState` 对应状态是否发生；是否误把面板物体 SetActive(false)（面板必须常驻激活，显隐由 CanvasGroup 控制） |
| 面板堆叠 / 点开始游戏后主菜单不消失 | v2 已由 UIManager 互斥 + CanvasGroup 自动获取修复；若复现，看 Console 是否有"同时声明显示于同一状态"的告警，检查两个面板的 ShownState |
| 暂停/死亡时角色/敌人还在动 | 说明 `timeScale` 未生效：确认状态确实切到了 Paused/PlayerDead（看 GameManager 的 State） |
| 复活后血条不显示 | 确认使用最新 `HealthBarUI.cs`（已加 `ShowBar` 自动恢复）；或血条预制体是否被改动 |
| 复活后卡住不能移动 | 若死亡瞬间正在攻击，`PlayerCombat` 需要等当前攻击动画播放完才解锁（约 1 秒内自动恢复），属预期 |
| 重新开始/返回主菜单报场景加载错误 | 确认 `Assets/Scenes/01-GameScene.unity` 已加入 `File → Build Settings → Scenes In Build`（本项目已加入） |
| 想跳过开始页直接进游戏 | 创建 `GameFlowProfile` 资产并把 `startState` 改为 `Playing` 后拖到 GameManager |
