# 背包与掉落系统 · 设计与使用说明

> 面向初学者的说明书。目标是让你搞清楚：**每个文件是干什么的、数据怎么从怪物身上走到背包格子里、想改东西该动哪里。**
> 阅读顺序建议：先看第 1~4 章（建立整体印象），再看第 6 章动手启用，第 7 章查字段，最后需要扩展时看第 8 章。

---

## 1. 一句话概括

怪物死亡时，一份"掉落表"决定掉什么，系统在地面生成能看见的实体；玩家靠近后按提示拾取，物品进入背包的数据格子，背包界面订阅数据变化自动刷新。

整个模块只做**增量接入**：没有修改 GameManager、PlayerController、ThirdPersonCamera、EnemyHealth、PoolManager 等任何既有脚本。

---

## 2. 全景图：数据是怎么流动的

```
          [怪物死亡]
               │  HealthComponent 广播 OnDied 事件
               ▼
     EnemyLootDropper（挂在敌人预制体上）
               │  只做一件事：拿到死亡坐标，交给生成器
               ▼
          LootSpawner（静态工具）
               │  1. 问 LootTable：这次掉什么、掉几个
               │  2. 在死亡点周围 1.2m 随机散开
               │  3. 向下打射线贴到地面
               │  4. 生成地面实体（对象池 / 实例化 / 空物体）
               ▼
        ItemPickup（地面实体）
               │  球体视觉 + Trigger 碰撞 + 注册到全局列表
               │
               │        PickupPromptUI 每帧找"离玩家最近的一个"
               │        ├─ 进入 3m → 屏幕下方显示最近物品的信息（不解锁光标）
               │        └─ 按 E → TryCollect(Inventory)
               ▼
           Inventory（背包数据，挂在玩家身上）
               │  尝试放入：先补已有同类堆，再占空槽
               │  任何变化 → 广播 OnChanged
               ▼
            InventoryUI（背包界面）
               │  收到 OnChanged → 刷新格子、数量、详情
               └─ 玩家拖拽 / 整理
```

**关键思想：一条线只往一个方向走。**
地面物品不认识 UI，背包不认识场景，UI 不认识敌人。每一层只和相邻的一层说话，所以你可以单独替换任何一层。

## 3. 文件地图：每个文件到底管什么

### 3.1 数据层（`Scripts/` 下，纯配置，没有逻辑依赖）

| 文件 | 一句话职责 | 你什么时候会碰它 |
|---|---|---|
| `ItemType.cs` | 物品分类枚举：材料 / 消耗品 / 装备 / 任务物品 | 想加新分类（如"宝石"）时加一个枚举值 |
| `ItemDefinition.cs` | 一种物品的"身份证"（ScriptableObject 资产）：ID、名字、描述、堆叠上限、图标、颜色、地面预制体 | 每次新增一种物品 |
| `LootTable.cs` | 掉落表（ScriptableObject 资产）：抽几次、散落半径、贴地层、候选条目及权重 | 每次新增一套掉落规则 |

> **ScriptableObject 是什么？**
> 它是一种"存在项目里、可以像资源一样双击编辑"的数据文件（`.asset`），不是挂在场景物体上的组件。
> 好处：100 个敌人可以共用同一张掉落表；改一次资产，所有引用它的敌人同时生效，不需要复制粘贴。

### 3.2 模型层（背包的"纯数据 + 规则"，完全不认识界面）

| 文件 | 一句话职责 |
|---|---|
| `InventorySlot.cs` | 一个格子：放什么物品（`Item`）、放几个（`Count`）。`Item == null` 就是空槽 |
| `Inventory.cs` | 背包本体：一串格子 + 增删查改 + 排序 + 跨背包转移 |

`Inventory` 对外只暴露"方法 + 返回值"，比如 `TryAdd` 返回**实际放进去几个**。拾取、交易、任务奖励都调同一套方法，界面不直接改格子里的数字。

### 3.3 世界层（地面上的东西）

| 文件 | 一句话职责 |
|---|---|
| `ItemPickup.cs` | 地面掉落实体：存"是什么/几个"，生成占位视觉，提供 `TryCollect` 拾取入口 |
| `LootSpawner.cs` | 静态工具：把掉落表结果变成地面实体（散落 + 贴地 + 池化） |
| `EnemyLootDropper.cs` | 挂在敌人上的组件：订阅死亡事件 → 调 `LootSpawner` |

### 3.4 表现层（`UI/` 目录，只负责显示和把鼠标操作翻译成数据请求）

| 文件 | 一句话职责 |
|---|---|
| `InventorySlotView.cs` | 一个格子的视图：显示图标和数量，把拖拽事件翻译成"请求" |
| `InventoryUI.cs` | 背包主界面：6 列网格、详情、拖拽、整理按钮、开关逻辑 |
| `PickupPromptUI.cs` | 屏幕下方的物品信息条（只展示最近的一件）+ E 键拾取，不接管鼠标 |
| `InteractionCursorGate.cs` | 光标/相机输入的"仲裁员"，让 UI 能点、关闭后能还原，且不改原代码（见 5.3） |

### 3.5 编辑器工具（已使用完毕并删除）

当初为了免去手写资产 GUID 的风险，做过一个 `Editor/InventorySetupWizard.cs`，一键生成测试物品、掉落表并完成场景/预制体接线。
接线完成后该工具已删除，现在 `Editor/` 目录为空。**已生成的资产、组件引用全部保留，不影响运行**；以后要新建物品请按第 8 章手动创建资产。

## 4. 三条核心链路，逐帧拆解

### 4.1 怪物死亡 → 地上出现物品

1. 玩家把怪物血打空，`HealthComponent` 内部把 `_isAlive` 设为 false，然后 **广播 `OnDied` 事件**（`OnDied?.Invoke()`）。
2. `EnemyLootDropper` 在 `OnEnable` 时订阅了这个事件，于是它的 `HandleDied()` 被调用。
3. 组件里有个 `_hasDropped` 标记，保证**一条命只掉一次**（对象池反复复用同一条怪物，这点很重要）。
4. 如果有 `dropDelay`，就延迟一会儿再掉（留给死亡动画用）；否则立刻调用 `Drop()`。
5. `Drop()` 拿到"怪物位置 + 0.6m 高度"，交给 `LootSpawner.Spawn()`。
6. `LootSpawner` 问 `LootTable.Roll()`：先随机 1~2 次抽取，每次按权重抽一条，再随机数量。
7. 每一条结果：以死亡点为中心，在半径 1.2m 的圆内随机一个点，然后**从点上方 2m 向下打一条 6m 的射线**，命中地面就把物品放到命中点往上 0.05m 处。
8. 生成物体：
   - 掉落表配了 `dropPrefab` 且场景有 `PoolManager` → 走对象池；
   - 只配了 `dropPrefab` → 直接实例化；
   - 都没配 → `new GameObject` + 挂 `ItemPickup`，由它自己生成**纯色球体**（零素材方案）。
9. `ItemPickup.Setup(物品, 数量)` 写入内容，创建视觉（球体）和 Trigger 碰撞球，并把自己登记进静态列表 `ActivePickups`。

> 为什么用 Trigger 碰撞而不是用物理检测拾取？
> Trigger 提供"独立碰撞判定"，让以后想做"踩上去自动拾取"或"物理爆炸把物品弹开"时有现成的接入点；当前的距离筛选则直接用坐标算，**不需要每帧 OverlapSphere**。

### 4.2 玩家靠近 → 拾取提示 → 进背包

1. `PickupPromptUI.Update()` 每帧检查：不是在 Playing 状态、或背包开着 → 隐藏，直接返回。
2. 遍历 `ItemPickup.ActivePickups`（倒序遍历，允许遍历中安全移除），算它和玩家（`Inventory` 所在物体）的距离，取 3m 内最近的一个。
3. 目标变化时：
   - 有新目标 → 显示底部信息条，文案 `[E] 拾取 生命药水 ×2`；
   - 目标消失（被销毁/寿命到期） → 隐藏信息条。
4. 按 E → `ItemPickup.TryCollect(Inventory)`。
5. `TryCollect` 调 `Inventory.TryAdd(物品, 数量)`：
   - 先往已有的同类堆里补；
   - 再占用空槽；
   - 返回实际放进去了几个。
6. 全部放进去了 → 地面实体回池/销毁；只放进去一部分（背包快满了） → **剩下的继续留在地上**，不会丢。
7. 一个都放不进 → 信息条文案变成"背包已满"。

> **为什么不提前扣地面物品再放背包？**
> 因为可能放不下。代码的约定是"先问背包能收多少，再按实际数量扣地面实体"，这样任何一步失败都不会凭空少东西。

### 4.3 打开背包 → 拖拽 → 整理

1. 按 `Tab` 或 `I` → `InventoryUI.Open()`：
   - 只在 `GameManager.IsPlaying` 时生效（主菜单/暂停/死亡不响应）；
   - 记录当前 `Time.timeScale` 后设为 0（冻结世界）；
   - 临时禁用 `PlayerController`（否则点 UI 会同时挥刀，因为攻击绑在鼠标左键）；
   - 向 `InteractionCursorGate` 申请"解锁光标 + 冻结相机视角"；
   - 刷新界面。
2. 拖拽分两步，**中间不动数据**：
   - `OnBeginDrag` → `BeginDragFromSlot(index)`：把"物品、数量、来源槽位"记进全局的 `ItemDragContext`，并显示一个跟随鼠标的图标。
   - 松开在目标格上 → `HandleDrop(targetIndex)`：这时才调用 `Inventory.Transfer(...)` 真正提交。
   - 松开在空白处 → `EndDrag()` 清空上下文，**什么都不会变**，所以拖拽中途取消不会丢物品。
3. `Inventory.Transfer` 的三条规则：
   - 目标空 → 直接放（整堆 = 移动）；
   - 目标同类 → 合并，目标堆塞不下的部分留在原位；
   - 目标不同类 → 只有**整堆**才交换，部分转移直接拒绝（避免出现"半个物品换掉别人"的怪情况）。
4. 点整理按钮 → `Inventory.Sort(mode)`：先把同类物品的总数聚合，再按规则排序，最后从第 0 格开始紧凑回填（超过单格上限会自动拆成多格）。
5. 任何数据变化都会触发 `OnChanged` → `InventoryUI.Refresh()` → 更新所有格子和容量文字。**UI 不需要知道是谁改的数据。**

## 5. 四个"为什么这么设计"（初学者最容易被绕晕的地方）

### 5.1 为什么背包是 `List<InventorySlot>` 而不是二维数组？

网格只是**表现**（`GridLayoutGroup` 按 6 列排）。数据层永远是"第 0 格、第 1 格……"，以后想改成 5 列、8 列、扇形排列，只改 UI，数据一行都不用动。

### 5.2 为什么 UI 不直接修改格子？

如果每个按钮、每次拖拽都去写 `slots[i].Count = ...`，规则就会散落在 UI 里，以后加"商店""仓库"时必然写第二份。现在所有规则集中在 `Inventory`，UI 只是"翻译鼠标操作 → 调方法"。

### 5.3 为什么需要 `InteractionCursorGate`？

场景里有两条既有规则：
- `GameManager` 每帧在 `LateUpdate` 把光标锁住（Playing 状态）；
- `ThirdPersonCamera` 直接读鼠标增量转视角。

如果背包直接解锁光标，下一帧就被 `GameManager` 锁回去；如果不禁用相机输入，移动鼠标会在点 UI 的同时转视角。
不改这两个脚本的解决办法：`InteractionCursorGate` 把自己的执行顺序设为 `900`（比 GameManager 的 `-100` 更晚），在它锁完之后再解锁；同时临时 `Disable` 相机自己的输入。用 `HashSet<Object>` 做引用计数，多个 UI 同时请求时，最后一个释放才真正恢复。

### 5.4 为什么掉落物用"预制体"作为对象池的键？

`PoolManager` 按预制体分池。所以 `LootTable.dropPrefab` 指向哪个预制体，就必须一直用**同一个引用**去 Spawn，池才会复用。如果你在代码里 `Instantiate` 一个再塞进池，是塞不进去的（会被当成手摆对象直接销毁）。

## 7. Inspector 字段速查

### 7.1 `ItemDefinition`（物品资产）

| 字段 | 说明 | 初学者建议 |
|---|---|---|
| `itemId` | 唯一 ID，留空自动用资产名 | 只用英文/数字，别改已有 ID |
| `displayName` | 显示名 | 中文即可 |
| `description` | 描述，显示在右侧详情 | 可留空 |
| `itemType` | 分类，影响排序与显示 | 从枚举里选 |
| `maxStack` | 单格最多叠几个 | 任务物品建议 1 |
| `rarityColor` | 槽位边框颜色 | 稀有度占位 |
| `icon` | 背包图标 | **留空 = 纯色方块**，有图再拖进来 |
| `iconColor` | 无图标时的占位色 | 随便选个能区分的颜色 |
| `worldColor` | 地面球体颜色 | 同上 |
| `worldPrefab` | 地面掉落物预制体（需挂 `ItemPickup`） | **留空 = 程序生成球体** |

### 7.2 `LootTable`（掉落表资产）

| 字段 | 说明 |
|---|---|
| `minRolls` / `maxRolls` | 每次死亡抽几次（1~2 表示随机） |
| `scatterRadius` | 以死亡点为圆心的散落半径（米） |
| `groundMask` | 贴地射线的层掩码。建议只勾地面层，避免贴到墙/怪物身上 |
| `dropPrefab` | 统一掉落物预制体。**留空则运行时生成占位实体** |
| `entries` | 候选列表：物品、数量区间、权重（权重 0 = 永不掉落） |

> 权重是相对的：铁矿石 55、药水 18，总权重 130 时，铁矿石概率约为 55/130 ≈ 42%。

### 7.3 `EnemyLootDropper`（敌人身上的组件）

| 字段 | 说明 |
|---|---|
| `lootTable` | 掉落表，留空则该敌人不掉落 |
| `dropDelay` | 死亡后延迟几秒才掉，接死亡动画后设成动画时长 |
| `heightOffset` | 掉落点相对根节点的高度偏移，默认 0.6，防止物品卡进地面 |
| `debugLog` | 是否在 Console 打印掉落记录 |

### 7.4 `ItemPickup`（地面实体）

| 字段 | 说明 |
|---|---|
| `item` / `count` | 内容，一般由代码设置，不要手填 |
| `bobHeight` | 上下浮动高度 |
| `spinSpeed` | 自转速度（度/秒） |
| `lifetime` | 存在时间（秒），0 = 永不消失，默认 180 秒 |

### 7.5 `Inventory`（玩家身上）

| 字段 | 说明 |
|---|---|
| `capacity` | 初始槽位数，默认 24（6 列刚好 4 行）。**改这里只影响新建**，运行时扩容要用 `SetCapacity` |

### 7.6 `InventoryUI`（`InventorySystem` 物体上）

| 字段 | 说明 |
|---|---|
| `toggleKey` / `alternateToggleKey` | 开关按键，默认 Tab / I |
| `pauseWhileOpen` | 打开时是否冻结世界（`Time.timeScale = 0`） |
| `blockPlayerInputWhileOpen` | 打开时是否禁用玩家控制（防止点 UI 触发攻击） |
| 界面引用（`uiRoot` 等） | **必填**。把 Hierarchy 里搭好的控件逐个拖进来，详见 8.8 |
| `slotPrefab` | **必填**。槽位预制体，每个格子实例化一份 |

### 7.7 `PickupPromptUI`

| 字段 | 说明 |
|---|---|
| `panelRoot` | **必填**。提示条根节点，靠近时显示、离开时隐藏 |
| `label` | **必填**。提示文字 |
| `pickupRange` | 提示触发的距离，默认 3m |
| `pickupKey` | 快捷拾取键，默认 E |

## 8. 我要加东西，改哪里？（扩展手册）

### 8.1 新增一种物品

1. 右键 `Assets/Main/Gameplay/Inventory/Data` → `Create → RPG/Inventory/Item Definition`
2. 填 `displayName`、`maxStack`、`itemType`，选一个 `iconColor`（不填图标也能跑）
3. 把它加进某张 `LootTable` 的 `entries`（或以后由任务/商店直接调 `Inventory.TryAdd`）

不需要改一行代码。

### 8.2 让一个新怪物掉落

1. 把它的血量组件换成继承自 `HealthComponent` 的版本（项目里 `EnemyHealth` 已经是）
2. 给预制体挂 `EnemyLootDropper`，把一张 `LootTable` 拖到 `lootTable` 字段

### 8.3 背包扩容

```csharp
inventory.SetCapacity(inventory.Capacity + 6); // 扩容总是成功
```

缩容只有在被裁掉的格子全空时才会成功（防止物品凭空消失）。

### 8.4 做宝箱 / 商店（跨容器转移）

```csharp
// 把玩家背包第 3 格整堆移到箱子背包第 0 格
Inventory.Transfer(playerInventory, 3, chestInventory, 0, playerInventory.GetSlot(3).Count);
```

`Transfer` 本身支持跨背包，拖拽 UI 只需要再做一个"箱子界面"，把落点指向另一个 `Inventory` 即可。

### 8.5 外部物品拖入背包

任何系统（任务奖励列表、商店货架）想让玩家用鼠标拖进背包：

```csharp
InventoryUI.Instance.BeginExternalDrag(itemDefinition, count);
```

调用后鼠标会拖着这件物品，放进任意格子即完成入包。注意：外部来源没有"原位"，放不下时由发起方自己负责退回（约定写在 `ItemDragContext` 注释里）。

### 8.6 换正式美术

| 想替换 | 怎么做 |
|---|---|
| 物品图标 | 把 Sprite 拖进 `ItemDefinition.icon` |
| 地面掉落物 | 做一个预制体（挂 `ItemPickup`），拖进 `ItemDefinition.worldPrefab`；或做统一预制体拖进 `LootTable.dropPrefab`（推荐，会走对象池） |
| 面板/按钮外观 | 直接在 Hierarchy / 预制体里换图、改 Image 与 Button 样式，代码不需要动 |

### 8.7 以后做"使用物品"

`Inventory` 已经预留了删除接口，外部调用即可：

```csharp
if (inventory.RemoveAt(index, 1))
{
    // 这里执行药水效果：回血、加 buff……
}
```

物品效果建议以后做成 `ItemDefinition` 上的可选资产（如 `IItemUseEffect`），不要在 `Inventory` 里判断 `if (item == 药水)`。

### 8.8 界面搭建（全部在 Hierarchy 里做）

背包和拾取提示的 UI **全部由 Hierarchy 搭建**，运行时代码不创建任何控件，只做两件事：显隐根节点、把鼠标操作翻译成数据请求。
这也是本模块"表现层与逻辑层分离"的体现：换皮只动 Unity 层级，不动一行代码。

#### 背包：第 1 步：搭 Hierarchy

建议结构（名字随意，层级关系别乱）：

```
InventorySystem            ← 常驻物体，挂 Inventory + InventoryUI（这个脚本不要挂在界面根节点上）
└─ InventoryCanvas         ← 界面根节点（挂 Canvas + CanvasScaler + GraphicRaycaster），拖到 uiRoot
   ├─ Scrim                ← 半透明遮罩（Image，铺满）
   ├─ Panel                ← 主面板
   │  ├─ Title             ← Text "背包"
   │  ├─ Capacity          ← Text "0 / 0"        → capacityText
   │  ├─ CloseButton       ← Button "×"           → closeButton
   │  ├─ GridScroll        ← Image + ScrollRect
   │  │  └─ Viewport       ← RectMask2D（铺满 GridScroll）
   │  │     └─ Content     ← GridLayoutGroup + ContentSizeFitter → gridContent
   │  ├─ Detail            ← 详情容器
   │  │  ├─ DetailIcon     ← Image               → detailIcon
   │  │  ├─ DetailName     ← Text               → detailName
   │  │  ├─ DetailType     ← Text               → detailType
   │  │  └─ DetailDesc     ← Text               → detailDesc
   │  ├─ SortByType        ← Button "按类型整理"  → sortByTypeButton
   │  ├─ SortByCount       ← Button "按数量整理"  → sortByCountButton
   │  └─ Hint              ← Text 操作提示
   └─ DragGhost            ← Image（初始隐藏）    → dragGhost
      └─ Count             ← Text               → dragGhostCount
```

要点：

- `Content` 必须挂 `GridLayoutGroup`（当前 8 列、格子 126×126、间距 12、内边距 14）；槽位由代码按 `Inventory.Capacity` 实例化，**不要**在 `Content` 下预放示例槽位。
- `GridScroll` 上挂 `ScrollRect`，`Viewport` 指向 Viewport，`Content` 指向 Content；`Viewport` 挂 `RectMask2D`。
- 所有文字用 `TextMeshProUGUI`（脚本字段是 `TMP_Text`），字体用 `SourceHanSansSC SDF`。

#### 背包：第 2 步：做槽位预制体（必做）

1. 搭一个槽位：根节点 Image（=边框，`Raycast Target` 必须勾）+ 子节点 `Bg`(Image) + `Icon`(Image) + `Count`(Text)
2. 根节点挂 `InventorySlotView`，把子控件分别拖到 `borderImage / backgroundImage / iconImage / countTextLabel`
3. 在 `InventorySlotView` 上按需改 `emptyBorderColor / normalBackgroundColor / hoverBackgroundColor`（想让自己的美术保持原色就填纯白）
4. 拖进 `Assets/Main/Gameplay/Inventory/` 存成预制体，再从场景删掉
5. 把预制体拖到 `InventoryUI.slotPrefab`

#### 背包：第 3 步：接线与验证

把上表中标注的控件逐个拖到 `InventoryUI` 对应字段 → 保存场景 → 运行按 Tab：

- 能开能关、按 Esc 无效但关闭按钮可用；
- 槽位数量 = `Inventory.Capacity`；
- 拖拽跟随图标正常、松手能交换/合并；
- 详情区悬停有内容。

> 常见坑：把 `InventoryUI` 挂在 `InventoryCanvas` 上（即 `uiRoot` 与本脚本同物体）会导致关闭后脚本被一起禁用、再也按不开背包——控制台会报错提醒，此时把脚本挪到外层 `InventorySystem` 即可。

#### 拾取提示条怎么搭

```
PickupSystem              ← 常驻物体，挂 PickupPromptUI（不要挂在 Canvas 上）
└─ PickupCanvas           ← Canvas（Sorting Order 建议低于背包，如 90）+ CanvasScaler + GraphicRaycaster
   └─ PromptPanel         ← Image，居中下方（约 420×72，锚点底部），拖到 panelRoot
      └─ Label            ← Text，铺满，拖到 label
```

要点：

- `PromptPanel` 的 Image 把 `Raycast Target` 关掉：它只做展示，不能抢鼠标；
- 初始可以把 `PromptPanel` 保持激活，运行后第一帧会自动隐藏；
- 拿不到 `panelRoot / label` 时脚本会报错并自动禁用，不影响其他功能。

## 10. 已知限制（都是有意为之，不是 bug）

1. **拾取提示固定用 E 键**：地面物品信息条只做展示，不会解锁光标、不会拦截鼠标，所以无法用鼠标点击拾取。想要改键就改 `PickupPromptUI.pickupKey`。
2. **地面掉落物最多存在 180 秒**：自动清理，避免长期堆积。想要永久保留就把 `lifetime` 设为 0。
3. **没有存档**：`Inventory.cs` 文件末尾留了 `CaptureState / RestoreState` 的实现思路（用 `itemId` 而不是资产引用），需要时再补 `ItemDatabase`。
4. **默认容量 24**：面板按 6 列 × 4 行设计，超过 24 会出现滚动条（`ScrollRect` 已经配好）。

## 11. 术语小词典（给第一次接触 Unity 架构的你）

| 词 | 在这里的含义 |
|---|---|
| **ScriptableObject** | 存在项目里的数据资产（`.asset`），可被多个场景/预制体共享引用。`ItemDefinition`、`LootTable` 都是 |
| **Prefab（预制体）** | 可复用的物体模板。敌人、未来的掉落物预制体都是 |
| **事件（event）** | "发生了某件事"的广播。`OnDied` 是死亡广播，`OnChanged` 是背包变化广播。订阅者收到通知后自己处理 |
| **订阅 / 退订** | `+=` 注册收到通知，`-=` 取消。必须在 `OnEnable`/`OnDisable` 成对写，否则对象池复用时会重复触发 |
| **接口（interface）** | 只约定"能做什么"的合同。`IHealthSystem` 约定有 `OnDied`，所以掉落组件不关心具体是哪种敌人 |
| **对象池（Pool）** | 反复创建/销毁物体很费性能，所以把不用的物体藏起来，下次直接拿出来复用。`PoolManager` 用预制体当键 |
| **Trigger** | 一种不产生物理推挤、只做"碰到检测"的碰撞体（勾了 `Is Trigger`） |
| **组件组合** | 不写一个巨大的 `Enemy` 类，而是把"血量""AI""掉落"拆成独立组件，需要什么挂什么。这就是本模块能不改既有代码的原因 |
| **执行顺序（Execution Order）** | 同一帧里脚本的先后。`InteractionCursorGate` 设成 900，是为了在 `GameManager`（-100）锁光标之后再解锁 |
| **静态类 / 静态列表** | `LootSpawner`、`ItemDragContext` 不需要挂到物体上；`ItemPickup.ActivePickups` 是全局登记表，方便 UI 查找 |
